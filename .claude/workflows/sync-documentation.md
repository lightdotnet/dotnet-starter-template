# Workflow: Sync Documentation

Triggered only by an explicit request to sync/update documentation.

## Steps

1. **Confirm scope.** Which backend module/project/folder or frontend area's docs are being synced, or is it genuinely all of them? Don't assume "all" unless the user says so.
2. **Diff each doc in scope**: delegate to [documentation-writer](../agents/documentation-writer.md) (or use facts already verified earlier in the session) to compare the existing doc against current code and determine what's added/updated/removed.
3. **Present one consolidated summary and get one approval.** Before writing anything, list every file that will change and, per file, a short summary of what will change. Ask for a single approval covering the whole batch — never ask file-by-file.
4. **Apply all approved changes**: once approved, write every file in the batch without asking again per file.
5. **Preserve manual documentation**: any clearly human-authored content (explicit "Notes"/manual sections, or content not previously generated by this workflow) must be kept verbatim.
6. **Remove outdated information**: stale facts that no longer match the code must be removed, not left contradicting reality.
7. **Keep all docs synchronized**: if a change in one doc has implications for another in scope (e.g. a backend overview and its dependency graph, or a backend API doc and the frontend integration notes in `.claude/ARCHITECTURE.md`), update both consistently within the confirmed scope — don't let them drift apart.
8. **Report**: a changelog-style summary of what was added, updated, and removed, per doc.

## Output

- A pre-write summary (files + planned per-file changes) with a single approval gate before any file is touched.
- Updated documentation files, scoped to what was confirmed, with manual content preserved.
- A summary of the sync (added/updated/removed) for the user to review.
