## Circular References

None found among internal module imports. `components/ui/*` is **no longer an absolutely strict leaf layer as of a prior sync** — `components/ui/dialog.tsx` and `components/ui/popover.tsx` both import `components/foundation/portal-container.ts`, a deliberate, narrow exception (a dependency-free React Context) added to fix a Dialog/Popover nested-scroll bug (see architecture.md Key Design Patterns). It remains true that `components/ui/*` never imports from `components/layout/*`, `components/theme/*`, or `features/*`, and no cycle results — `components/foundation/*` doesn't import back from `components/ui/*`. Cross-feature page-level barrel imports observed so far (`features/auth` → `features/user-profile`, `features/users` → `features/user-profile`, `features/notifications` → `features/user-profile`) go one direction only, through the target feature's barrel. The `features/users` → `features/roles` and `features/notifications` → `features/users` barrel edges removed in a prior sync remain gone (`users-page.tsx` no longer fetches the role catalog, `notifications-page.tsx` no longer fetches `getAllUsers`); each was replaced by a component-level, direct-file, cross-feature edge instead (`edit-user-dialog.tsx` → `features/roles/api/get-all-roles-action.ts`, `user-select.tsx` → `features/users/api/search-users-action.ts`) — counted among the barrel-bypass exceptions below, not barrel imports. Six narrow, reasoned exceptions to the barrel-only rule now exist — `constants/nav-items.ts`, `components/layout/user-menu.tsx`, `components/layout/topbar.tsx`, `edit-user-dialog.tsx` (→ `get-all-roles-action`), `user-select.tsx` (→ `search-users-action`), and `home-page.tsx` (→ `notification-inbox.tsx`, `get-my-notifications-action.ts`) — each importing one specific file directly instead of through a barrel; see architecture.md. All six are driven by the RSC client/server boundary: the target barrel also re-exports an async Server Component (`UsersPage`/`RolesPage`/`NotificationsPage`/`LoginPage`) that calls `resolveSession()`/reads cookies via `next/headers`, so importing the full barrel from a `"use client"` component (or, for `nav-items.ts`, from client-side `Sidebar`) would drag that server-only chain into the client bundle — this was tried and produced a real "next/headers only available in Server Components" build error before being fixed this way; `home-page.tsx` is the one exception where the importer is itself an async Server Component (not subject to the client-bundle constraint), and no comment in its source explains the direct-file choice — noted as an observed fact, not a confirmed rationale. A seventh, lower-level exception exists at the `lib/server` tier: `lib/server/refresh-session.ts` imports `features/auth/api/token.api.ts` directly (bypassing the `@/features/auth` barrel, which does export `refreshToken`) — worth noting since it's also a reversal of the usual `features/* -> lib/server/*` direction (here, `lib/server` reaches into a feature's `api/` file), unlike the other six exceptions which stay within the normal direction. `lib/server/require-permission.tsx` does **not** share this reversal — it imports `features/user-profile`'s barrel the same way ordinary page code does. `components/shared/data-table/*`, `components/shared/object-viewer/*`, `components/shared/access-denied.tsx`, and `components/toast/*` are consumed by feature code (or, for `access-denied.tsx`, by `lib/server/require-permission.tsx`) but import nothing from `features/*` themselves, so no cycle there either. `components/foundation/*` and `components/command/*` import only `@floating-ui/react`/`@tanstack/react-virtual`/`lucide-react`/`react`/each other — no `features/*` dependency, no cycle. (`components/select/*`, the third member of this group in a prior sync, is deleted.) `features/home` is imported only by `app/(dashboard)/page.tsx` (routing) and reaches into `features/notifications` via two direct-file imports (part of the six exceptions above, not a separate case) — no cycle results, since neither `features/notifications` nor `features/user-profile` imports back from `features/home`.
